What works today
Today you canWith
Deploy a Docker Compose app to a server you own, signed on your machinezekno deploy
Keep secrets encrypted for that one serverzekno secret set import
Describe an app by settings in place of a Compose filezekno settings
Add a database, its passwords made on your machinezekno add postgres
See what is running, read logs, roll backzekno zekno logs zekno rollback
Not built yet: teammates, the hosted service, the desktop app, domains with HTTPS, building from source. See the roadmap.
Try it
git clone https://github.com/zekno-app/zekno && cd zekno && bun install cd apps/cli && bun run compile # dist/zekno cd ~/my-app && zekno deploy # asks for your name, the server, the app
The quick start shows each step with what you will see. Zekno is not packaged yet, so it is built from this repository with Bun 1.4.4.
How it works
Today: your machine talks to your server
No Zekno service is involved. Keys live at the two ends.
Your machine
zekno, the CLI
Holds your key
Encrypts secrets
Signs each deploy
over SSH
sealed secrets, signed deploy
Your server
Runner
Verifies the signature
Decrypts with its own key
starts
Your containers
Docker Compose
Planned: a hosted service in the middle, holding nothing it can open
The design this project exists for. Teammates, deploy history and a desktop app arrive with a hosted service that stores only ciphertext and signed deploys. It is not built yet. The two diagrams and the step-by-step of today's README follow here, unchanged, under this heading.
