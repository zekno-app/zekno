Deploy version 2: the runner's refusals, one app line, and the README's note
Every reason a runner can give gets its own sentence, so none falls to "The runner refused the request (…)".
A runner answers a refusal with one fixed word, never with a name, so these sentences name no app and no secret. Each keeps the habit of today's refusals: what happened, that nothing ran, then what to do. They are said the same way by zekno deploy, zekno rollback, with no terminal (one line on standard error) and on the app's deploy screen.

One line of the app's deploy screen changes
Under a refused deploy the app shows Number 42 is used, so the next deploy will be 43.. With version 2 a refusal uses no number, so that line would be false: it is left out after a refusal, and kept when the app was accepted but did not start, where it is still true.
The README's note on what the hosted service can read (and the same on the docs' security page)
Today
The control plane still sees metadata: server addresses, app names, deploy times and team membership.
Proposed
The control plane, when it exists, will never see a secret's value. It will see:
·Server addresses and team membership
·App names, deploy numbers and times
·Each deploy's Compose text with its plain variables, and image names with their digests
·Each secret's name, version, size and who set it
With domains, building from source and health checks, it will also see:
·Domains
·Build recipes and their arguments, pre-deploy commands, health-check paths
·The size and fingerprint of each source pack: enough to confirm a guess of the exact source (a public repository at a known commit), not to read it
