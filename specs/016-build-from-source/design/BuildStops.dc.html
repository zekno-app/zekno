Build from source: every stop before signing
Approved on 2026-11-27. Every stop of zekno deploy before anything is signed, rows C1 to C21c of lines.md: the size and the number of files, an empty folder, a file that cannot be read, changed or named, a Compose file that builds, the images and the ADD lines refused, the limits on plain variables and builds, a missing stage or Dockerfile, a secret-looking file with no yes, --fresh with nothing to build, several Dockerfiles and none named, a folder zekno never sends, and an app name an image cannot take. Example values only.
Each stop comes before anything is signed or sent, and ends with exit status 1. At a terminal its sentence stands alone after ✖, as every stop before the deploy panel does today: the first sentence bold and on one line with its mark, the rest dim under it, and commands without their backticks. With no terminal, or with --json, the same words are one plain line on standard error, backticks kept; a terminal wraps that line at its edge. In the full-screen app the sentence is the deploy screen's result line, in the error colour, under ✖ Checked (lines.md, part C). Every line on this board is new. The choices of this board were decided on 2026-11-27. A sentence written after that approval is a draft: its note says so, and it is shown to the maintainer before its screen is built.

Rename it, or list it in .dockerignore. Nothing was signed.
C1 and C2 name what takes the most room. A deploy carries 512 MiB, said as 537 MB as zekno prints sizes, and 50,000 files and folders. C3 is an empty folder; C4 a folder whose every file is left out. C7 shows the name cleaned; its other ending for a name is its name holds a control character. C7's last form, its path is too long, is for a path the pack's form cannot hold, with no / that splits it into a folder part of at most 155 bytes and a name of at most 100 (plan item 16 (a)). It replaces the form its name is longer than 255 bytes, and a path too long for one line is shortened in its middle with …. Only that form is a draft. New · C8 to C13 · a Compose file, the Dockerfile's images and ADD lines
What a build may start from and fetchzekno deploy
$ zekno deploy
✖ compose.yaml asks Docker to build web.
zekno builds from a settings file only: run zekno settings init to start one. Nothing was signed.
$ zekno deploy
✖ compose.yaml names zekno.invalid/shop, a name zekno reserves for the images it builds.
Use the image's own name. Nothing was signed.
$ zekno deploy
✖ The Dockerfile of web starts from zekno.invalid/blog, an image built for another app.
A build starts only from images in a registry. Nothing was signed.
$ zekno deploy
✖ The Dockerfile of web names an image zekno cannot work out: FROM ${BASE} on line 1.
Give BASE a default in its ARG line, or set it with zekno settings set web.plain.BASE <image>.
Nothing was signed.
$ zekno deploy
✖ The Dockerfile of web fetches https://example.com/tool.tar.gz with ADD and no checksum (line 12).
Add --checksum=sha256:<hash> to that line. Nothing was signed.
$ zekno deploy
✖ The Dockerfile of web fetches http://10.0.0.5/setup.sh with ADD, a private address (line 12).
A build cannot fetch from the server or its private network. Nothing was signed.
C8 and C9 are for a Compose file written by hand. zekno.invalid is the space reserved for the images zekno builds: C10 also stops an image of that space named through an ARG default, a plain variable, or a copy from another image. C13 stops an address that names the server itself or a private one, with a checksum or not.

New · C14 to C17 · the limits on plain variables and builds
More than a build or a deploy can carryzekno deploy
$ zekno deploy
✖ The build of web would read 33 plain variables, over the 32 a build can carry.
Remove the ARG lines it does not need, then deploy again. Nothing was signed.
$ zekno deploy
✖ API_URL is 5,120 bytes, over the 4,096 bytes a build can carry for one value.
Shorten it, or remove ARG API_URL from the Dockerfile of web. Nothing was signed.
$ zekno deploy
✖ shop's builds would read 71,680 bytes of plain variables, over the 65,536 a deploy can carry.
Remove the ARG lines they do not need, then deploy again. Nothing was signed.
$ zekno deploy
✖ shop would build 9 images, over the 8 one deploy can build.
Run some services from an image, or build several from one Dockerfile and stage. Nothing was
signed.
The limits: 32 plain variables a build, 4,096 bytes for one value, 65,536 bytes of plain variables for a deploy, and 8 builds a deploy. A build reads a plain variable only when its Dockerfile declares it with ARG, so C14 to C16 count only those.

New · C21a to C21c · several Dockerfiles, a folder never sent, a name an image cannot take
No Dockerfile named, the home folder sent, a name ending with a hyphenzekno deploy
$ zekno deploy
✖ zekno.app.json names no Dockerfile for web, and the folder sent holds several.
They are Dockerfile, Dockerfile.prod and api/Dockerfile. Set one with zekno settings set
web.dockerfile <path>. Nothing was signed.
$ zekno deploy
✖ The source.root of web is your home folder, /Users/ada.
zekno never sends your home folder or its own. Set the project's folder with zekno settings set
web.root <folder>. Nothing was signed.
$ zekno deploy
✖ The app shop- cannot be built, since an image name cannot end with a hyphen.
Deploy it under a name that ends with a letter or a digit, with zekno deploy --app <app>. Nothing
was signed.
C21a: the settings leave out build.dockerfile, and the folder sent holds several Dockerfiles in FR-004's sense, a Dockerfile beside a Dockerfile.* or one in a sub-folder that is sent (plan item 23; contracts/cli.md CL7 step 3), in C18's pattern. C21b: source.root is, or holds, the home folder or zekno's own folder (ZEKNO_HOME, else ~/.zekno), compared by real path (plan item 23; contracts/cli.md CL2). Its first sentence has three other forms: The source.root of web holds your home folder, /Users/ada., The source.root of web is zekno's own folder, /Users/ada/.zekno. and The source.root of web holds zekno's own folder, /Users/ada/.zekno. C21c: the app's name ends with a hyphen, which an image name cannot, so its builds are refused (plan item 15 (a)). Written after the approval of 2026-11-27; not yet seen by the maintainer.
