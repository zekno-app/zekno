# Tasks: Templates

**Input**: Design documents from `/specs/012-templates/`

**Prerequisites**: plan.md, spec.md, the boards in design/ (binding), research.md, data-model.md, contracts/ (template-file.md, commands.md, contributing.md), quickstart.md

**Tests**: included. The constitution requires unit tests for logic with branches (Principle VII), and the spec requires an automatic test of every template (FR-023), a failure injected at every step of adding (SC-004), no made value anywhere (SC-002), real Docker for each template (SC-008), `plain-unchanged.test.ts` green (SC-006) and an independent security review.

**Organization**: grouped by user story, in priority order (US1 P1; US2 and US5 P2; US3 and US4 P3). Paths are relative to the repository root; commands run in `apps/cli` unless said otherwise. Within a pair, the test task comes first and is seen to fail. At the end of every task: `bun test` in `apps/cli` passes for what the task touched, `bun run lint` in `apps/cli` finds nothing, and `bun run format` in `apps/cli` leaves no change but the task's own files. At the end of every phase the whole of `bun test` in `apps/cli` passes.

**Before you start**: nothing waits for the maintainer. Read plan.md, "Needs the maintainer" (N1 was answered: an index file) and "Design choices, approved by the maintainer" (D1 to D33, each built as approved there, D27 changed to status 1; the task that builds each says so). The boards were redrawn on 2026-11-17 after the plan (design/README.md); where a board shortens a digest, zekno prints it whole (D25). Every look and sentence no board shows is built as the contracts write it and listed in your report.

**Sentences** are quoted from the contracts by their ids: TR1 to TR4, TF1 to TF34 (TF34 added by the security review, T5), TC1, TC2 and the TS mapping in contracts/template-file.md; AD1 to AD29 (AD2 and AD26 unused; AD29 added by the security review, T1), AU1 to AU10, AL1 to AL4, AV1 to AV6, AH1 to AH9 and the summary's words in contracts/commands.md; CG, TT, CW, TD and MS in contracts/contributing.md. Copy them from there exactly; they live in `apps/cli/src/templates/file-words.ts` and `apps/cli/src/templates/add-words.ts`. Never use the word "agent" for any part of Zekno: the program on a server is the runner. No em dash in any sentence. Every file under 500 lines.

**Never**: change a file under `packages/core/` or `apps/runner/`; edit `apps/cli/test/plain/plain-at-head.ts`, `apps/cli/e2e.config.ts` or anything under `apps/cli/tests/`; read, print or copy `apps/cli/.env.local`; add a dependency; run `next dev` or `next build`; use the real keychain or `~/.zekno` (tests use `memoryKeyStore()` and a temporary `ZEKNO_HOME`); `ssh` to any host; contact a server; use ports 3000 or 3100. Docker is used only by T031, T036 and T043's optional check, with Compose projects named `zekno-test-template-<name>` or `zekno-<app>` of a temporary app, publishing no port, each removed with its volumes at the end.

## Format: `[ID] [P?] [Story] Description`

- **[USn]**: the user story it serves.

or not at all, proven with real Docker. A developer adds a database and deploys.
