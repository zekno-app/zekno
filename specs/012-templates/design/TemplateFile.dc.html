What each part is
name, title …What the list and the docs page show. The author is credited.
alsoNames people may type instead, such as mongo for mongodb.
servicesWhat goes into zekno.app.json. Same format, same checks. Its volume data becomes postgres-data in the app, so no two services share one.
makesSecrets made at random on the user's machine.
offersA connection secret for the user's own services. {service} is the service's name in their app.
notesSentences shown before adding. Backups are always named.
asksQuestions to the user, such as a domain. Kept for the version that brings domains. Refused until then.
What a file cannot do
It is data, read strictly: no code, no unknown field, nothing fetched. It cannot mount a folder of the server, run privileged or publish a port, because settings cannot say those.

How one gets in
1. Copy a template file, change its values, and add its name to the index, one line.
2. Run the template tests.
3. Open a pull request. The tests run again on GitHub, with no access to any secret.
4. A maintainer reads it and merges it.
5. It ships with the next release, in zekno add and on the docs page, with its author.
What the reviewer checks by hand
Is it the software's official image?
Is the description honest about what it does not do?
Does it need a setting that weakens it?
A start command that runs a shell: every word of it.
