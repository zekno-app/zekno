A Compose file written by hand
$ zekno add postgres
This folder deploys from compose.yaml, a file written by hand.
Zekno does not edit it. Add these lines yourself.
Under services:
postgres: image: postgres:18.7@sha256:2ea8…1bbc restart: always environment: POSTGRES_USER: app POSTGRES_DB: app POSTGRES_PASSWORD: ${POSTGRES_PASSWORD} volumes: - postgres-data:/var/lib/postgresql
Under volumes:  postgres-data:
In the environment: of each service that uses it
DATABASE_URL: ${DATABASE_URL}
? Make and store its two secrets for demo on prod? (y/N) yes
✔ Stored POSTGRES_PASSWORD and DATABASE_URL, sealed for prod
Piped, the lines are printed as they are and no secret is made without --yes.
When it cannot add. Nothing is changed
No server yet, so nothing to seal a secret for:
✖ There is no server to keep secrets for yet.
Run zekno deploy first. It sets up your team and a server.
The app has this template already:
✖ demo already has a secret named POSTGRES_PASSWORD.
A template can be added once to an app in this version.
A service of that name exists:
✖ zekno.app.json already has a service named postgres.
Give this one another name with --name <service>.
A service already reads a variable of the connection secret's name:
✖ web already has a variable named DATABASE_URL.
Remove it, or leave web out with --for <service>.
The file changed while the question was open:
✖ zekno.app.json changed while this was open.
Nothing was added. Run zekno add postgres again.
A folder with no settings file and no Compose file:
✖ This folder has no settings file.
Run zekno settings init to start one, then add the template.
Exit status 2. The last two are 1, as zekno settings gives for the same cases.
In a script
With no terminal it never asks. Without --yes it stops:
Adding a template changes zekno.app.json and stores secrets. Say --yes to go ahead.
With --yes, plain lines:
added postgres zekno.app.json stored POSTGRES_PASSWORD 1 stored DATABASE_URL 1
With several services and no --for, it stops and names the flag. It does not guess who reads the secret.
Never shown
A made secret's value is in no line, no error, no file and no argument. Only its sealed record holds it.
