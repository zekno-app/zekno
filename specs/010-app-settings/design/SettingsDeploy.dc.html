When the file cannot be used
It asks for something a later version brings. Nothing is deployed:
✖ zekno.app.json sets a domain for web.
Domains are not in this version of zekno yet.
It is not in the right form. The place is named, never the content:
✖ zekno.app.json could not be read as settings.
web, deploy.memory: use a size such as 512m or 1g.
It has a field this zekno does not know:
✖ zekno.app.json could not be read as settings.
web, deploy: a setting this zekno does not know (line 9).
With no terminal and both files, it stops. Exit status 2:
This folder has zekno.app.json and compose.yaml. Say which with -f <file>.
Which file a deploy uses
1. -f <file>, either kind.
2. The file this folder's link (zekno.json) names.
3. The one that exists, when only one does.
4. With both and nothing above: it asks at a terminal, and stops in a script.
Neither file is ever picked silently over the other.
What does not change
Your machine turns the settings into Compose text and signs that. The server sees what it sees today.
